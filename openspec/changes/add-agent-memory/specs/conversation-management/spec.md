## Purpose

会话生命周期管理：让用户能创建、切换、重命名、删除对话会话，浏览历史会话列表，从后端恢复历史消息。为短期记忆提供组织容器，前端提供侧边栏交互。

## ADDED Requirements

### Requirement: 会话 CRUD

系统 SHALL 提供会话管理 API：创建会话（自动生成标题或用户指定）、列出当前用户所有会话（按最后活跃时间倒序）、获取会话详情、重命名会话、删除会话（级联删除消息）。所有操作 MUST 按当前登录用户隔离。

#### Scenario: 创建新会话

- **WHEN** 用户点击"新建对话"
- **THEN** 系统创建新 conversation 记录，生成唯一 ID
- **AND** 前端切换到新会话，后续消息携带新 conversationId

#### Scenario: 列出历史会话

- **WHEN** 用户打开会话列表
- **THEN** 返回该用户所有会话，按最后活跃时间倒序
- **AND** 每个会话显示标题、最后消息预览、消息数、时间

#### Scenario: 删除会话级联

- **WHEN** 用户删除一个会话
- **THEN** 该会话及其所有消息被删除
- **AND** 不可再通过该 conversationId 发送消息

### Requirement: 会话切换与历史加载

用户切换会话时，前端 SHALL 从后端加载该会话的完整历史消息并渲染。加载 MUST 支持分页（会话消息可能很多），默认加载最近 N 条（如 50 条），向上滚动加载更早消息。

#### Scenario: 切换会话加载历史

- **WHEN** 用户从会话 A 切换到会话 B
- **THEN** 前端调用 API 加载会话 B 的历史消息
- **AND** 渲染完整对话记录（用户 + 助手消息）
- **AND** 后续发送消息使用会话 B 的 conversationId

#### Scenario: 分页加载长会话

- **WHEN** 一个会话有 200 条消息，用户向上滚动到顶部
- **THEN** 系统加载更早的 50 条消息
- **AND** 不一次性返回全部 200 条避免性能问题

### Requirement: 会话标题自动生成

新会话首条用户消息发送后，系统 SHALL 基于该消息自动生成简短标题（截取前 20 字或由 LLM 摘要生成）。用户 MAY 手动重命名。

#### Scenario: 自动生成标题

- **WHEN** 用户首条消息是"帮我分析下 NPE 报错的原因"
- **THEN** 会话标题自动设为"NPE 报错分析"或消息前 20 字
- **AND** 用户可点击重命名修改

### Requirement: 前端会话侧边栏

前端 Chat 页面 SHALL 新增会话列表侧边栏，展示所有历史会话，支持新建、切换、重命名、删除操作。侧边栏 MUST 与主对话区联动，切换会话时主区刷新历史。

#### Scenario: 侧边栏交互

- **WHEN** 用户在侧边栏点击某个历史会话
- **THEN** 主对话区加载并渲染该会话历史
- **AND** 当前激活会话在侧边栏高亮

#### Scenario: 移动端适配

- **WHEN** 视窗宽度小于 768px
- **THEN** 侧边栏默认折叠为抽屉，点击菜单按钮展开
- **AND** 切换会话后自动收起
