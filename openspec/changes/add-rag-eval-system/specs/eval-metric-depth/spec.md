## Purpose

扩展指标维度覆盖"答得对"之外的质量：忠实度（答案是否仅由检索片段支撑，防幻觉）、时延（检索与端到端性能）、文档维度分层（定位哪份语料拖后腿），使评测结论从"能不能用"深入到"好不好、慢不慢、哪里差"。

## ADDED Requirements

### Requirement: LLM-as-judge 忠实度评分

生成层评测（LLM 门控开启时）SHALL 对每条用例调用裁判模型：输入为该题的回答与实际注入的检索片段，输出 1~5 整数忠实度分与一句理由；报告 MUST 输出平均分与逐条分数。平均分低于 4.0 MUST 判定生成层评测失败。裁判调用失败（超时/API 错误）SHALL 将该条记为 null 并从平均分中剔除，报告 MUST 展示裁判覆盖率（成功打分条数/总条数）；覆盖率低于 0.8 时 MUST 判定失败并提示检查裁判模型可用性。

#### Scenario: 答案含片段外信息

- **WHEN** 某用例的回答包含检索片段中不存在的数字
- **THEN** 裁判给出低分（≤2）并在理由中指出无依据的表述
- **AND** 平均分被该条拉低，可能触发失败

#### Scenario: 裁判服务不可用

- **WHEN** 裁判模型 API 全部调用超时
- **THEN** 覆盖率为 0，生成层评测判定失败并提示检查裁判模型

### Requirement: 时延统计

检索层评测 SHALL 逐用例记录检索耗时（含查询向量化），生成层 SHALL 记录端到端耗时；报告 MUST 输出 p50 与 p95，并按查询类型分组展示检索时延均值。时延 SHALL 写入归档 summary.json。

#### Scenario: 报告中的时延分布

- **WHEN** 一次完整评测（检索层 32 条 + 生成层 14 条）完成
- **THEN** 报告含检索 p50/p95、端到端 p50/p95 四个数字
- **AND** summary.json 中可按用例回查耗时

### Requirement: 文档维度分层

检索层报告 SHALL 在查询类型分层之外，增加按预期命中文档分组的 Recall@4 / MRR / Top1 均分表，用于定位"哪份语料的块质量拖后腿"。

#### Scenario: 定位弱语料

- **WHEN** 某文档相关用例的 MRR 显著低于其他文档
- **THEN** 文档维度表中该文档行可直接对比看出差距
